# 合并规则

两个主实验各自只有一个 `experiment.json`。按 benchmark 的原始任务 ID 和算法轮次建立唯一记录；seed、A/B/C 角色、实际模型和配置保持原含义。目录分组不再表示启动、重启或续跑批次。

合并以原最终报告接受的候选及其原生评分回执为准，不通过“最新文件”或“最高分”重新挑选。WorkBuddy 保留 50 × 3 × 3 = 450 个分数，Claw-Eval 保留 104 × 3 × 3 = 936 个分数。运行时实际选择的 arm 与事后官方成绩分别记录，零分不会被视为缺失。

同一任务的续跑产物放入同一任务目录。真正不同的失败、修订或替换尝试保留为证据，不作为额外成功样本；Claw-Eval 的 37 次 actor 替换及实际输出额度修订有独立记录。被评分或历史分析引用的不同内容即使原文件同名，也按原始内容哈希分别保存。模型或协议条件改变不会因合并目录而被抹去。

四个完成的关联分析按其实际分析条件保存：原始联合评分、技术修复、官方分差子集和 midpoint。它们使用冻结时的候选、Pack 与原生成绩；不会被后来完成的主实验候选替换，也不被描述为新的在线实验。

公开清单同时记录原始身份哈希和规范化后的文件哈希。原始到公开路径的映射、未经修改的记录、旧批次结构和中间报告只保存在本机 archive，既能追溯，也不成为下载后复现的依赖。
